# dsh-boss-job v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付一个可 `npx dsh-boss-job` 安装的开源求职助手：CLI + Skill + MCP 三入口共用一套零依赖 core，在用户真实登录的 Chrome 里搜索/读 JD/硬筛/出报告，并发布到 GitHub 与 npm。

**Architecture:** 零运行时依赖的 Node ESM CLI（`src/cli.mjs` 分发，`src/core/*` 各管一件事：Chrome 启动、CDP、登录态、搜索、详情、偏好、筛选、报告），`src/mcp.mjs` 以换行分隔 JSON-RPC 暴露同一批能力；`skills/boss-job/` 是给宿主 agent 的流程文档，三层访谈与评分由 agent 执行。所有运行期数据只写 `~/.dsh-boss-job/`，专用 Chrome profile 与用户默认 profile 完全隔离。

**Tech Stack:** Node ≥ 18（内置 `fetch`、`WebSocket`、`node:test`、`util.parseArgs`），零 dependencies / 零 devDependencies，MIT。

**Spec:** `E:\找工作\设计文档-boss-job.md`

## Global Constraints

- Node ≥ 18，全部源码为 ESM `.mjs`；`package.json` 的 `dependencies` 与 `devDependencies` 必须为空。
- 运行期数据只写 `~/.dsh-boss-job/`（可用 `BOSS_JOB_HOME` 覆盖）；绝不读写用户默认 Chrome profile。
- 不引入 Playwright / Puppeteer / Selenium / MCP SDK；CDP 与 MCP 协议手写。
- 请求间隔 2500–4500ms 随机；单次运行详情 ≤ 60 个；检测到 code 37、安全验证页、登录失效立即停止。
- v0.1 只读：不发消息、不投递、不改账号状态。
- CLI 面向用户的中文文案；README 中文（`README.md`）+ 英文（`README.en.md`）。
- 每个 Task 结束时 `node --test` 全绿并单独 commit。
- 许可证 MIT，包名 `dsh-boss-job`，bin `dsh-boss-job`（别名 `boss-job`），仓库 `gro83j/dsh-boss-job`。

## Review Focus

1. **Chrome 缺失或装在非标准路径**：`dsh-boss-job doctor` 必须退出码 2 并打印可操作提示（候选路径列表 + `--chrome <path>` 用法），不能抛栈。
2. **端口冲突 / Windows 排除段 / 残留 runtime.json**：复用存活实例，否则重选端口重启，任何情况都不能挂起；Windows 上跳过 9201–9300。
3. **Boss 前端改版**：解析函数遇到缺失选择器时返回已解析字段 + `warnings`，CLI 提示“页面结构可能变了，跑 doctor --selftest”，不得返回半截脏数据当成功。
4. **中途登录失效**：检测不到 `wt2` 时中止剩余抓取、保留已保存数据、提示重新 `dsh-boss-job login`。
5. **非 ASCII 路径/城市名/JSON**：所有读写显式 UTF-8，用户输入只经参数传递，不拼进 shell 命令。

- [ ] **Step 2: 运行确认失败**：`node --test test/cdp.test.mjs`。

- [ ] **Step 3: 实现**

`CDP` 内部 `this.pending = new Map()`；`send` 写 `{ id, method, params }`，注册 `{ resolve, reject, timer }`，`timeoutMs > 0` 时 `setTimeout` reject `CDP timeout: ${method}`；`onopen` resolve `open()`；`onmessage` 解析 JSON：有 `id` 则按 pending 结算（`error` 时 reject `error.message`），否则按 `method` 派发；`onclose/onerror` 时把所有 pending reject 并清空。`open` 支持 `timeoutMs`。

`evalJs` 构造 `Runtime.evaluate` 参数，结果取 `result.result.value`；`result.exceptionDetails` 存在时抛 `Error(exceptionDetails.text + ' ' + (exceptionDetails.exception?.description ?? ''))`。

`listTargets` GET `/json/list`；`ensurePage` 先找 `type==='page' && url.includes('zhipin.com')`，找不到就 `fetch('/json/new?url=' + encodeURIComponent(url), { method: 'PUT' })`，返回 `{ id, wsUrl: webSocketDebuggerUrl }`。
