# Phase 4：评分与报告

目标：给用户一份能直接照着投的清单，而不是一堆链接。

## 步骤

1. 逐条读 JD（不是只看标题）：职责、硬性要求、工具、类目、工作制。
2. 按 phase2 的 rubric 打 4 个分（0–5），算 `score`，写一句 `reason`（≤ 40 字）。
3. 生成报告：`dsh-boss-job export --input <details.json> --evaluation <eval.json>`。
4. 报告结构：
   - 一句话结论（这一轮值不值得投）；
   - 主投 3–5 个：岗位/公司/薪资/为什么合适/投递前要补的一句话；
   - 备选 2–4 个：差在哪；
   - 剔除清单：按原因分组（薪资、年限、排除词、排除岗位/类目、活跃度……）；
   - 风险提示：信息不全、疑似外包、单休、薪资结构与下限不符。
5. 结尾问用户：要不要针对某个岗位改简历 / 准备自我介绍。

## 质量要求

- 主投岗位必须至少读过 JD 正文，不能只凭标题。
- 薪资写页面原文，不要换算；「7-10K·13薪」照抄。
- 不夸大匹配度：用户只有 7 个月助理经验时，3-5 年岗要明说够不着。
- 不推荐需要用户明确排斥的工具、岗位或类目（以访谈里确认的 exclude/avoid 为准）。
