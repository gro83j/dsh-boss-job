# Phase 0.5：入口分流与职业方向探索

在问城市、薪资这些「怎么找」之前，先确认两件事：**你是谁、你有没有目标**。这两个问题决定接下来走哪条路，不要跳过。

## 第一层：入口两问（必须最先问）

按顺序问，一次只问一个：

1. **你现在是学生吗？**（在校本科/研究生/应届已毕业，都算学生；已工作选「不是」）
2. **你已经有心仪的岗位了吗？**（能说出具体岗位名，比如「电商运营」「新媒体运营」；说不出来就是「没有」）

四个分支：

| 学生 | 有心仪岗位 | 走向 |
| --- | --- | --- |
| 是 | 是 | 直接进 Phase 1 偏好访谈（跳过职业探索） |
| 是 | 否 | 进「学生方向探索」→ 产出 1–2 个方向 → Phase 1 |
| 否 | 是 | 直接进 Phase 1（顺带问一句「为什么想转」即可，不展开） |
| 否 | 否 | 进「转行/重启方向探索」→ 产出 1–2 个方向 → Phase 1 |

说「不确定 / 都行 / 你帮我选」的，按「没有目标」处理，不要替用户拍板。

## 第二层：方向探索（只有「没有目标」才走）

目标不是给用户灌鸡汤，而是把「我能做什么、市场要什么、我愿意付什么代价」对齐，收敛出 1–2 个可以马上去搜的方向。

### 第 1 轮：盘点现状（3–4 问，一次问完一轮）

学生版：

- 学校、专业、年级？如果已经毕业，毕业多久了？
- 做过哪些事？实习、社团、兼职、比赛、自己做过的项目，挑 2–3 个说细节（你具体负责什么、结果如何）。
- 你比较擅长/做得比别人快的是什么？不一定是职业技能。
- 家里人/经济上对你的选择有什么约束？（城市、考公考研、必须尽快挣钱……）

转行版：

- 之前做什么？做了多久？为什么想离开？
- 哪些能力是可迁移的？（对人、对数据、对内容、对流程……）
- 能接受多长的空窗/降薪/从助理做起？
- 有没有「绝对不想再碰」的工作方式？（出差、应酬、倒班、纯执行……）

### 第 2 轮：偏好与排斥（2–3 问）

- 钱、成长、稳定、兴趣，只能保两个，你选哪两个？
- 最不想做的工作是什么样的？（用具体场景问，不要问抽象的「价值观」）
- 有没有现实门槛？学历、证书、作品集、体检、地域。

### 第 3 轮：把方向摆到台面上（不提问，先给判断）

基于前两轮，给 **3–4 个候选方向**，每个写清：

- 为什么匹配你（引用用户的原话/经历，不要模板话）；
- 入门门槛（学历/经验/技能/证书，哪些你现在就够、哪些要补）；
- 起步薪资区间与成长路径（用真实岗位数据，能搜 BOSS 就搜，不要编）；
- 这个方向最难受的地方（诚实说，比如「前 6 个月就是打杂」「要背指标」）。

然后让用户选 1–2 个。用户选完，把方向写进 `~/.dsh-boss-job/career-plan.md`，并转成 Phase 1 的 `directions` 草稿。

### 输出：career-plan.md

写在 `~/.dsh-boss-job/career-plan.md`（或报告目录），结构：

1. 个人画像（3–5 句，引用用户真实经历）
2. 技能盘点（硬技能 / 软技能 / 待补）
3. 推荐方向 2–4 个（匹配理由、门槛、薪资、成长、难点）
4. 30 / 60 / 90 天计划（具体到「这周做什么」）
5. 诚实的风险（哪些假设可能不成立）
6. 下一步：进入 Phase 1 的三个问题（城市/薪资/方向）

## 规则

- 一次只问 1–3 个问题，等回答再继续；不要甩问卷。
- 不评判用户的学校、专业、空窗期；把「非标准路径」当资产问细节。
- 方向结论必须落到可搜索的岗位名，不能停在「适合做运营」这种半成品。
- 薪资、门槛尽量用 BOSS 实时数据（可先 `search` 一轮验证需求），查不到就写「未知」，不要编。
- 用户如果聊到一半说「算了直接找」，尊重选择，带着已有信息进 Phase 1。
- 方法论参考了 MIT 许可的 [career-coach](https://github.com/Jeff-Kazzee/career-coach)，文本为本项目自写。
