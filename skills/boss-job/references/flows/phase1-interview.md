# Phase 1：偏好访谈

目标：把「想找什么样的工作」变成可执行的 `preferences.json`。

开始前先按 `phase05-career.md` 问两个入口问题：**你是学生吗？你已经有心仪的岗位了吗？** 没有目标时先按 phase05 的建议去咨询/整理信息（本项目不做职业规划），方向定了再回来做这里的三层访谈。

**不问清楚就不采集**：不预设行业、不预设岗位、不替用户填城市或薪资。分三层，逐层确认，不要一口气问完。

## 原则

- 问题用用户自己的话复述后再落盘；拿不准就追问，不要猜。
- 每一层结束，把答案回读一遍：「我记下的是……对吗？」
- 用户没提到的字段保持空值（`null` / `[]`），空值表示**不过滤**，不是「随便设一个默认」。
- 排除项只记录用户**原话**里的词，不要替用户补充「常见该排除的岗位」。

## L1 硬条件（必答）

1. 工作城市？可以多选，国内城市，支持跨地区/多城市（例：城市A + 城市B，或只限某个区）。直接说城市名即可，CLI 会解析成 BOSS 城市 code，不需要用户背 code。
2. 薪资：下限多少？有没有上限（超过多少就不考虑）？
3. 岗位方向？可多选，用用户自己的说法；不要替用户归类。方向超过 3 个时，帮他排优先级。
4. 绝对不接受什么？（例：某类岗位、某类公司、单休、出差……没有就说不接受项为空）

## L2 深挖（两轮，合并提问）

第一轮：经历与边界

- 相关经验多久？（用于判断岗位写的「1-3 年」「3-5 年」这类要求是否偏高；应届/转行也可以说没有）
- 有不想投的岗位级别吗？如果要排除，请用户自己说标题里会出现哪些词，记进 `excludeTitles`。
- 有没有「看到就放弃」的硬性要求？例：必须会某个工具、必须会外语、必须带团队、必须驾照……这些记进 `avoid` 或 `excludeJdKeywords`。

第二轮：偏好与取舍

- 行业/类目：优先哪些？明确不要哪些？（只写用户说的，不要补）
- 公司类型/规模：大厂、创业公司、外包、国企……有偏好吗？
- 工作制：双休是否硬性？加班/大小周/出差能否接受？
- 招聘者活跃度：只看最近几天活跃的，还是都可以？（默认不过滤）
- 地点细节：只要某区，还是全城都可以？

## L3 搜索计划（给用户确认，不直接开跑）

输出一张表：关键词 × 城市 × 预计页数 × 预计详情数，并标注风险：

- 关键词太宽会混入不相关岗位（例：只搜一个很泛的词，会混进其他职能）；
- 组合词更准（岗位词 + 行业词/平台词），但会漏掉命名不规范的岗位；
- 单轮详情 ≤ 60，超过要分批，并说明会花多久。

用户确认关键词和范围后，才开始 Phase 3 采集。

## 写盘

把结果写进 `~/.dsh-boss-job/preferences.json`（MCP 用 `boss_prefs_set`，CLI 可直接写文件）。空值表示不过滤：

```json
{
  "cities": [{ "name": "城市A", "code": "待填" }],
  "salary": { "floor": null, "ceiling": null },
  "directions": [],
  "experienceMonths": null,
  "activeDays": null,
  "avoid": [],
  "keywords": [],
  "excludeTitles": [],
  "excludeCategories": [],
  "excludeJdKeywords": []
}
```

字段含义：

- `avoid`：排除词，命中标题或标签即剔除（按用户原话，如「外包」「单休」）。
- `excludeTitles`：排除的岗位名片段，命中标题即剔除（按用户原话填写）。
- `excludeCategories`：排除的行业/类目片段，命中标题或标签即剔除（按用户原话）。
- `excludeJdKeywords`：只在 JD 正文里匹配的排除词（如「外包」「出差」「某工具」），命中即剔除。
- `experienceMonths`：用户自述的相关经验月数；填了才把岗位年限之和它的下限比较，`null` 表示不判断。
- `activeDays`：填了才过滤招聘者活跃度；`null` 表示不判断。

写完回读一遍给用户确认，尤其是薪资、方向和「绝对不接受什么」。
