# Phase 1：偏好访谈

目标：把「想找什么样的工作」变成可执行的 `preferences.json`。分三层，不要一口气问完。

## L1 硬条件（必答，4 问）

1. 城市？（默认杭州；给出 `cities: [{name, code}]`，BOSS 城市 code 如杭州 `101210100`）
2. 薪资下限？（月薪，单位元；只卡下限，上限不设死）
3. 方向？（电商运营 / 新媒体运营 / 直播运营 / 类目运营……可多选）
4. 最不能接受什么？（例：纯投流、服装类目、单休、销售性质）

## L2 深挖（两轮，合并提问）

- 经验与层级：正式工作经验几个月？助理/专员/主管？——用于过滤「3-5 年」「组长」。
- 类目偏好与排斥：美妆/食品/饮料/宠物/日化……明确不要的类目写进 `avoid.categories`。
- 工具边界：直通车、万相台、千川会不会？不能接受的写进 `avoid.keywords`。
- 工作制：双休是否硬性？加班/大小周能否接受？
- 活跃度：只聊最近几天活跃的招聘者？（默认 3 天）

## L3 搜索计划（给用户确认，不直接开跑）

输出一张表：关键词 × 城市 × 预计页数 × 预计详情数，并标注风险：

- 关键词太宽（如「运营」）会混入主播/客服/销售；
- 类目词 + 平台词（如「天猫 美妆运营」）更准；
- 单轮详情 ≤ 60，超过要分批。

## 写盘

把结果写进 `~/.dsh-boss-job/preferences.json`（MCP 用 `boss_prefs_set`，CLI 可直接写文件），结构：

```json
{
  "cities": [{ "name": "杭州", "code": "101210100" }],
  "salary": { "floor": 7000 },
  "directions": ["电商运营"],
  "experienceMonths": 7,
  "activeDays": 3,
  "avoid": { "categories": ["服装"], "keywords": ["直通车"] },
  "keywords": ["美妆运营", "食品运营"]
}
```

写完回读一遍给用户确认，尤其是薪资下限和「不要什么」。
